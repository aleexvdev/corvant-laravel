# Security Policy

Corvant handles authentication, sessions, and access control for applications that install it —
security issues here have real impact. If you find one, please report it privately rather than
opening a public issue.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting for this repository:

**[Report a vulnerability](https://github.com/aleexvdev/corvant-laravel/security/advisories/new)**

This opens a private draft security advisory visible only to the maintainer until it's resolved
and you agree to disclose it. Please include:

- A description of the vulnerability and its potential impact
- Steps to reproduce it (a minimal test case or request sequence is ideal)
- The affected version(s), if known

Please do not open a public GitHub issue for security reports, and please don't test a
vulnerability against a production deployment you don't own.

## Supported versions

| Version | Supported |
|---|---|
| 1.x     | ✅ |

Corvant is pre-1.x-stabilization software adopting semver from `v1.0.0`. Security fixes land on
the latest `1.x` release; there is no long-term-support branch at this stage.

## What to expect

This is an independently maintained open-source project — there's no SLA, but security reports
get priority over everything else. You'll get an acknowledgement, then updates as the issue is
triaged and fixed. Credit is given in the advisory unless you ask to stay anonymous.
